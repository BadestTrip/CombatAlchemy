# Potion Instance And Physical Entity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every valid mix create one unique potion that can be held, drunk, thrown, or placed while preserving a clean future storage boundary.

**Architecture:** `PotionRecipeData` remains immutable formula data. `PotionInstance` represents one produced potion, `HeldPotionSlot` owns the current instance and physical node, and one scene-backed `PotionEntity` changes state from held to flying or placed before resolving effects exactly once.

**Tech Stack:** Godot 4.7.2, typed GDScript, scene-backed `Node2D`/`Area2D`, `ShapeCast2D`, headless Godot scene tests.

**Spec:** `docs/superpowers/specs/2026-08-29-potion-instance-entity-design.md`

## Global Constraints

- Preserve current main menu, settings, pause, music, transitions, Player movement, camera, recipes, and capability-based potion effects.
- Preserve all unrelated uncommitted changes; stage only task-owned files.
- Keep `PotionRecipeData` and effect resources immutable at runtime.
- Implement one held slot and one-use potions only; no inventory UI, stacking, pickup, or save/load.
- Bind `place_potion` to physical `Q`; place `64.0` pixels along current mouse aim.
- A valid impact consumes the instance even when zero effects are supported.
- Use `apply_patch` for manual edits and add tests before implementation.

Use this helper for every Godot command so Windows waits for the real editor process:

```powershell
$godot = 'D:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe'
function Invoke-GodotWait([string]$arguments) {
    $psi = [System.Diagnostics.ProcessStartInfo]::new()
    $psi.FileName = $godot
    $psi.Arguments = $arguments
    $psi.WorkingDirectory = (Get-Location).Path
    $psi.UseShellExecute = $false
    $process = [System.Diagnostics.Process]::Start($psi)
    $process.WaitForExit()
    if ($process.ExitCode -ne 0) { throw "Godot exited $($process.ExitCode)" }
}
```

Create `PotionDelivery.gd`:

```gdscript
extends RefCounted

```

Create `PotionInstance.gd` with private `_recipe`, copied `_created_layers`, and `_consumed`. `create()` must validate both `recipe.is_valid()` and `recipe.matches_layers(layers)`. Implement:

```gdscript
static func create(recipe: PotionRecipeData, layers: Array[StringName]) -> PotionInstance:
    if recipe == null or not recipe.is_valid() or not recipe.matches_layers(layers):
        return null
    var potion := PotionInstance.new()
    potion._recipe = recipe
    potion._created_layers.append_array(layers)
    return potion

func apply(context: PotionImpactContext) -> int:
    if _consumed or not is_valid() or context == null or not context.is_valid():
        return 0
    _consumed = true
    return PotionEffectResolver.apply_recipe(_recipe, context)

func discard() -> bool:
    if _consumed:
        return false
    _consumed = true
    return true
```

Return copies from `get_created_layers()`. `is_valid()` requires a valid recipe, three matching copied layers, and no null recipe.

Change `PotionImpactContext.delivery_method` and `configure()` from enum/int to `StringName`. Accept unknown non-empty IDs and use `PotionDelivery.THROW` only for an empty ID. Remove the old enum.
